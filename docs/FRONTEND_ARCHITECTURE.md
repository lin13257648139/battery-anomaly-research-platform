# 前端重构方案与实现

## 产品任务

界面用于分析公开动力电池充电数据：先了解数据规模和模型结论，再定位车辆、检查信号、核对工程作业，最后判断结果是否可用。异常标签属于公开数据的事后真值；页面不能把它展示成实时模型预测。

## 信息架构

| 工作区 | 用户任务 | 已实现交互 |
|---|---|---|
| 运行总览 | 快速把握数据规模、模型表现和高风险车辆 | 指标卡、模型对照图、风险排序、点击车辆进入诊断 |
| 车辆诊断 | 寻找并检查某辆车 | 编号搜索、正常/异常标签筛选、车辆选择、信号切换、抽样序列图 |
| 模型实验 | 判断模型是否真的有效 | AUROC/AP、95% 区间、车辆隔离协议、低片段数敏感性结果 |
| 数据管道 | 核验处理规模和一致性 | Spark 输入/输出、耗时、与 pandas 的逐列误差、历史回放去重 |
| 系统状态 | 看清可用能力和边界 | 数据/API 状态、公开来源、接口文档、非实时与非云端声明 |

## 技术架构

- `frontend/`：React 19、TypeScript、Vite、Recharts、Lucide；共用面板、指标与标签组件，构建时进行类型检查。前端只请求 `/api`，不读取原始 pickle。车辆时序数据进入诊断页后按需加载。
- `service/api.py`：FastAPI 只读接口；`/summary`、`/vehicles`、`/vehicles/{car}/series`。长记录车辆按批次抽样，避免一次性加载全部信号到前端。
- `frontend/nginx.conf`：静态资源与 `/api` 同源代理，避免浏览器跨域配置；本地只暴露 `127.0.0.1:18501`。
- `compose.yaml`：API 与前端两个容器。旧 Streamlit 页面已从运行栈移除。

## 人机交互约束

1. 五个工作区遵循从概览到证据的渐进披露；车辆行可直接钻取。
2. 搜索、筛选、切换信号均有明确控件标签；主导航和按钮保留键盘焦点样式。
3. 加载、空结果、接口失败和重试都有可见状态；移动端导航折叠。
4. 图表直接显示数据，不依赖入场动画；不依赖外部字体服务，断网可用。
5. 始终区分“源标签”“模型分数”“历史模拟回放”，禁止把模拟时间解释为真实预警时间。

## 已验证与待补强

已通过 TypeScript 和 Vite 生产构建；Docker Compose 可启动；本地首页和 `/api/health` 返回 200；宽屏页面已经浏览器截图核对。窄屏页面的卡片和导航已经适配；当前 headless Edge 在 390 像素截图时可能保留更宽的内部布局视口，因此未把该截图当成完整的移动端验收。

若要对公网生产发布，还需身份认证与权限、API 速率限制、可观测性、真实用户场景测试、浏览器交互回归、无障碍审计、云端弹性与成本实测。这些并非当前本地实现已完成的能力。
